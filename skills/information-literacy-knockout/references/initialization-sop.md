# 淘汰赛对话初始化 SOP

目标是在计时开始前，建立正文正确、设置可见、输入输出可用的个人或团队对话。准备、能力试跑和正式开始是三件事；用户只要求准备入口时，停在零题就绪状态。

## 1. 确认本轮设置

沿用本轮已经确认的信息，只补影响操作的缺项：

| 项目 | 要确认的内容 |
| --- | --- |
| 场景 | 赛前准备、官方样题、明确的模拟练习，或已确认规则允许的手动辅助 |
| 环节与时间 | 个人／团队，题数和总时限；本包模板为 10 题／300 秒、10 题／900 秒 |
| 计分与页面 | 正确、错误、跳过如何计分，多选有无部分分，能否返回，翻页及超时行为 |
| 输出 | 默认唯一推荐答案＋一句判据；需要提示模式时预先说明 |
| 模型 | 用户选定的产品、实际模型名称和界面档位；不要把历史测试当当前最优推荐 |
| 会话偏好 | 现有或新对话、临时或保存、是否需要个人与团队两个入口 |

训练模板不是赛事公告；不要自动继承旧年份的范围排除、平台入口、录屏留存日期或计分。缺少页面规则只标未验证，在模拟或彩排中核实，不点击正式考试开始来试功能。未知能否返回时，不依赖“最后再补查”。

确认规则后，若需要改题数、时限、输出模式或资料范围，先调整将发送的模板文本，使完整正文与本轮一致。不要只在标题写新设置、正文仍留旧时限。计分有扣分时，推荐候选供选手决策，不自动推导为所有题都必须填答。

## 2. 选择使用入口

### 支持 Skill 的 Agent

提供整个目录，调用 `information-literacy-knockout`，要求读取 `SKILL.md` 和本轮对应的全文。检查宿主实际读取了这些文件；技能安装成功或显示名称只证明入口存在。

### 普通聊天窗口

打开用户选择的聊天产品，使用可发送图片的正常聊天窗口。无需假定它支持原生 Skill。后续将全文作为一条普通用户消息发送；不要只上传一个包含未知依赖的入口文件，也不要只说“沿用上次 P1”。

个人与团队建议分别准备窗口，并使用容易区分的名称。两者各自加载对应正文，不在同一计时对话中来回覆盖。保存、命名或新建按用户要求执行，不擅自修改账号记忆、训练或隐私设置。

## 3. 先选模型，再发送全文

1. 在当前窗口选择本轮模型与档位。以界面实际可见设置为依据；没有该型号就报告缺项，不悄悄换模型。
2. 从 [个人模板](../assets/personal-chat-init.txt) 或 [团队模板](../assets/team-chat-init.txt) 复制全文，包括最后的就绪要求。题数、时限等已经按第 1 步修改时，使用修改后的完整文本。
3. 一次性发送，等待“准备好了”。不要把占位消息、文件标题、版本号或上一对话的答复当本轮正文加载。
4. 回读已发送的实际消息，核对全文、个人／团队标记、时限和结尾。支持全文比对时与所选文本逐字比较；仅能手动查看时确认消息完整，未经全文核验就标“完整性未验证”。模型复述版本名或回复“准备好了”不能代替正文检查。
5. 再核对实际模型与档位。部分环境可能在新建、发送或刷新后改变设置；发现变化就标记并在发题前纠正。需要重发或重新生成就绪回复时，只处理初始化消息，不把旧题带入新练习。

若初始化报错，保留失败状态，先确认消息是否实际发送，避免连续重复提交。可以在零题状态按正常界面恢复或重建一次；同一错误继续出现就报告本轮尚未就绪，不无限开新窗口。

## 4. 检查必要网站与能力

按本轮范围只检查会用到的来源，不要求登录所有数据库。登录、扫码、验证码和机构绑定由使用者完成，不复制凭据到其他环境。

| 检查对象 | 有效的就绪证据 |
| --- | --- |
| 比赛入口 | 由可信赛事通知进入，用户确认本人和当前场次；检查准备页，不启动正式考试 |
| 赛事指定工具，如知网 AI、LeapSpace | 使用官方或本校入口，执行一次不含试题的普通查询，目标结果可读；头像或首页不证明目标权限 |
| 指定数据库 | 进入正确子库，核查询条件和新结果；仅在任务需要时核全文权限 |
| AI 读图 | 用户手动发送清晰的自编测试图，题干、否定词和全部选项可被正确识别 |
| AI 检索 | 用非考题事实读取一个可访问的原始公开来源；只说“可以联网”不算实际结果 |
| 操作与设备 | 窗口切换、截图、发送、阅读和手动填答路径可完成，电源与网络可用 |
| 录屏（有要求时） | 按当场要求用短测试确认文字和操作可辨认、空间足够；留存周期按实际通知 |

先把来源路径分清：助手能直接访问、用户合法登录后可查看、当前无法取得。用户浏览器已登录不等于普通聊天的云端检索也有权限。不要读取或导出 Cookie 来“打通”环境。

能力试跑在用户要求检查链路或开始练习时执行。**只要求建立零题入口时，不擅自发测试题**，把未测能力列出来。若需要零题正式待用窗口，可先在独立练习对话试跑，再按第 3 步初始化待用窗口；前者证明链路曾可用，后者仍须独立核全文与设置。

## 5. 记录就绪状态

用一个小表即可，用户不要求落盘时保留在当前对话，不新建复杂日志系统：

| 项目 | 状态 | 依据或缺口 |
| --- | --- | --- |
| 环节、时限与模板 | 已观察验证／用户报告／未验证／不适用 | 本轮文本版本和训练参数 |
| 已发送正文 | 同上 | 全文是否核对，是否截断或混入另一模板 |
| 模型与档位 | 同上 | 初始化之后实际可见的设置 |
| 就绪回复 | 同上 | 是否收到正常完整回复 |
| 题目与草稿 | 同上 | 若要求零题待用，应为 0 题、0 附件、空草稿 |
| 图片、检索及操作 | 同上 | 分项记录实际试跑，不能用一项替代其他项 |
| 恢复入口 | 同上 | 当前标签页、用户保存入口及恢复是否实测 |

初始化总结只需三项：已就绪项；未就绪项及影响；下一步最短动作。可以说“零题对话已初始化，图片和检索未测”，不能简化为“全部通过”。不要承诺固定响应上限。

## 6. 保存、刷新与恢复

使用者需要长期保留时，按产品正常功能保存或命名，并在赛前、零题时验证能否恢复。只使用该用户自己的入口，不分享私人聊天链接。

- 已保存对话：重新打开后检查原初始化全文、可见模型档位及现有消息是否保留；不能从同名标题推断上下文相同。
- 临时对话：是否可恢复取决于宿主行为；未经验证不要依赖 URL 或刷新保留正文。需要重新建立时重发全文，不假定跨对话记忆会补齐。
- 正文在但设置变了：先纠正设置，必要时重新生成就绪回复；只确认发生过的检查。
- 正文缺失、历史混乱或重复提交：在用户同意的正常对话流程中重新建立入口，沿用完整模板；不删除原对话来制造“干净”状态。
- 计时中断线或访问失败：不要随意刷新答题页、丢失本题或假设计时暂停。报告故障与影响，由选手按已确认规则处理。

恢复验证可能改变对话状态，只在用户要求保存／恢复或已明确授权的准备工作中执行。已经确认的正常入口不必每题重查。

## 7. 交给选手使用

用户明确开始练习后，执行“完整题图 → AI 短答 → 本人判断 → 手动填答”。保持同一轮的模型与文本，不逐题重建聊天，不额外要求选手在限时内人工搜集原文。

题面缺失可以补图；搜索没有决定性证据则按模板标不确定。为诊断而额外提供原文的实验，须单独设计和报告，不能把供原文条件下的成绩当作只发截图的效果。结束后按 [练习与复盘](practice-and-review.md) 记录实际覆盖与未验证项。
